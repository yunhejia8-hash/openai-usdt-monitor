# OPENAI-USDT-SWAP 行情与交易节奏监控

只使用 OKX 公共行情 API 和已确认的 15m / 1H / 4H K 线，不连接账户、不下单。
`schema_version=8` 保留，新增 `strategy_version=risk_v9`。已有指标、状态、历史账本字段继续保留。

## 本次改进的范围

修复未收复支撑仍可试仓、首次突破绕过回踩限制、空头 SETUP 遮盖多头候选的问题；
补充含成本的收益风险比、试仓止损统计和分批退出计划。
**规则合格不代表已证明盈利。** 固定历史回放没有证明本版收益提升；结果见
[验证报告](docs/risk-v9-validation.md)。严禁把 BuyScore/EntryScore 当成胜率。

## 入场过程

指标与权重不因本次回放调优：MA5/10/20、BOLL(20,2)、RSI6/12/24、
MACD(12,26,9)，柱值为 2×(DIFF−DEA)、ATR10、SuperTrend(10,3)、量比和结构。
Bias 仅描述环境，不授予下单许可。

- BuyScore = 25% 支撑质量 + 20% 阻力环境 + 20% 趋势 + 15% 动量 + 10% 量能 + 10% 结构。
- EntryScore = 45% 位置 + 20% 支撑质量 + 15% 趋势 + 10% 动量 + 10% 量能 − 追涨扣分。
- Location = clamp(100 − 50×|现价−支撑|/ATR, 0, 100)。
- MA20 偏离改用本次成交价计算，超过2 ATR扣25分，超过3 ATR禁止入场；距离支撑超过1.2 ATR也禁止即时买入。
- 支撑质量、趋势、动量等是规则分数；来源、各条件、阈值保留在 JSON 中。

| 状态 | 约束 |
| --- | --- |
| WAIT | 不满足候选，观望 |
| SETUP | 接近条件，仅观察 |
| PROBE | 距支撑≤0.8 ATR；现价和已确认K线均收复支撑，且该K线曾触及支撑；无有效跌破；Location≥60、支撑质量≥38、Buy≥55、Entry≥58；四个早期信号至少2个；原始与含成本R:R均≥1 |
| CONFIRMED | 维持线上更严格的结构、阳线回踩、SuperTrend、量比≥1.10及MACD确认；Buy≥65、Entry回踩≥70/突破回踩≥68；原始与含成本R:R≥1.5 |
| ADD | 先满足CONFIRMED、明确已有仓位，再满足趋势强化、Buy≥72、Entry≥75、Location≥70、MA20偏离≤1.5 ATR；原始与含成本R:R≥2 |

四个早期多头信号：15m SuperTrend向上、MACD柱>0、量比≥0.85、RSI6在45～75。
已登记的突破必须等后续已收盘K线完成回踩确认，不能通过PROBE提前追入。
支撑锚点仅在0.8 ATR附近延用，不能让远离现价的失效支撑永久锁住策略。

止损位置沿用线上定义：PROBE为支撑−0.75 ATR；正式入场使用结构失效位
（支撑下方超过0.2 ATR的最近支撑，无则锚点−0.2 ATR）。两者风险不同，不应混用。
未改变既有空头方向能力；SHORT_PROBE增加对应的已收盘阻力拒绝与净R:R条件。
多空同时满足可入场条件时改为冲突观望；SETUP不遮盖另一方向可入场候选。

`limit_order_allowed` 和价格区域保留兼容，但只是预备计划，**不能单独作为下单许可**。
必须同时检查 entry_state、risk_assessment 和实际持仓。程序不会发出订单。

## 收益与风险输出

`net_probe` / `net_confirmed` 分别输出含成本的净R:R、目标收益百分比、止损亏损百分比。
默认每边手续费5bps、滑点5bps只是研究假设，不代表实际OKX费率；同时输出每边2/5/10bps敏感性。
不含资金费、精确强平或订单排队。跳空损失可能超过计划值。

`break_even_target_first_rate` 是只有“到目标/止损”两种结果时的理论盈亏平衡命中率，
不是预测胜率，也不适用于超时退出或完整分批卖出收益。
账户计划亏损%=名义持仓占权益%×止损亏损%÷100。名义持仓已经包含杠杆时，不再乘一次杠杆。

风险原因包括行情过期、多空冲突、逆4H趋势、量能弱、未确认收复、首次突破等待、
追涨、净空间不足、成本相对止损过大、试仓统计不足。
重大变化检测增加风险原因变化、空头状态变化、退出动作变化和止损/止盈线移动。

## 小仓试仓的止损概率

每次PROBE冻结当时的止损、第一目标、入场区域、方向、4H趋势及版本。
分别统计信号后下一根15m开盘仍符合冻结区域、净R:R和防追涨条件时，
**未来4小时/24小时内，首次到目标之前先触及初始止损**的历史模拟频率。

- 下一根开盘不合格：记为未入场，不能伪造一个失败或成功交易。
- 按24小时观察区间去重；只有完整到期、连续且已确认的K线才计入。
- 同根K线同时触及目标和止损：先后不明，输出上下界，不捏造顺序。
- 同版本、同方向、同4H趋势匹配；旧账本没冻结价位时排除，不能事后猜止损。
- 至少30个样本、无先后不明事件且Wilson 95%区间宽度≤30个百分点时，才提供历史点估计。
- 其余返回 `probability_estimate=null`，同时显示样本数和区间；这是未知，绝不是0%风险。
- 当前候选统计不足会警告；历史止损频率≥60%会额外警告。60%仅为提醒阈值，不是已验证的交易过滤器。

输出位于 `strategy.low_risk_entry.stop_risk` 和 `performance_tracking.probe_stop_risk`。
这不是完整交易的最终亏损概率，也不是经样本外验证的下一单概率。市场相关性与环境变化仍存在。
原 `horizon_stats` 是未扣成本的信号方向观察收益，不再称作账户净收益。

## 分批卖出和加仓节奏

`execution_plan` 只分析手工提供的持仓，不把信号当成交。
没有上下文时返回 `position_context_required`，不假设有持仓。

1. 先检查当前保护止损及趋势退出（1H趋势不利且15m SuperTrend不利）。
2. 先判断旧目标是否已到达，再提出目标调整，避免目标上移吞掉已触发的止盈。
3. 第一阶段卖出当时持仓25%；第二阶段卖出当时持仓70%，保留当时持仓30%。
4. 趋势仍好时，依据已确认指标形成的新阻力/支撑向有利方向调整未完成目标，不能反向放宽。
5. 第二阶段完成后，尾仓用1H SuperTrend提出保护止损；止损只收紧，不放宽。
6. 加仓不重置已完成止盈阶段；正在止盈/全平或只剩尾仓时暂停新增同向仓位。
7. 已持仓新增需信号等级高于上次真实成交等级，并另行核验总风险预算。重复候选不是重复买入指令。
8. 手工上报止损后，冷却两根15m K线。

示例：100份→第一阶段卖25份→加20份后持有95份→第二阶段卖66.5份→留下28.5份。
没有加仓时，两次后保留最初仓位22.5%，不能写成最初仓位30%。

可选环境变量 `POSITION_CONTEXT_JSON`（Actions映射同名Secret，默认不配置），格式：
```json
{"side":"long","quantity":100,"initial_stop":95,"stop":96,"tp1":105,"tp2":110,"tp1_done":false,"tp2_done":false,"last_filled_entry_state":"PROBE"}
```
这是虚构示例。数量仅供规则上下文，未假定OKX合约张数等于币数；`last_stop_ts` 可选，毫秒UTC。
持仓参数需在真实成交后人工更新；动态目标/止损仅是建议，用户采用后也需回填，脚本不擅自记作执行成功。
公开输出不包含原始持仓数量，但会展示计划价位和阶段，请勿输入账户密钥或其他个人资料。
兼容的 `HAS_POSITION` / `HAS_SHORT_POSITION` 仅代表明确已有仓位，不足以计算实际账户风险。
30分钟行情扫描无法替代交易端实时保护单，也可能错过盘中触及后回撤的止盈。

## 运行与验证

```sh
pip install -r requirements.txt
python -m unittest -v
python -m py_compile monitor.py trade_risk.py replay_probe_risk.py
python monitor.py
```

Windows可能需要 `tzdata`。Actions保留10分钟冗余调度探测，25分钟新鲜度门槛使实际行情刷新约30分钟；
GitHub调度不是准点承诺，原健康监测与watchdog继续保留。
任何规则修改都应先验证数据时序、成本、重复信号、退出阶段，再做未参与开发的新区间验证。
